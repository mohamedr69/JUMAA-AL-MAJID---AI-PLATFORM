## Override principle (applies to every field)

One target authority means one domain owner of the fact. Automatic extraction and engineer edits are inputs to that owner's controlled write path. Observations (`DOC.records`, `DOC.form_reading`, `DOC.evidence`, `CLS.*`, map cells) are stored apart from the effective value. Who may override: the engineer roles the routes already require (CREATOR_ROLES / editor roles). TARGET: an existing override survives new input. TODAY this holds for drawings (confirmed_by_id on drawings and revisions), BOQ lines (origin=corrected), compliance (approval fingerprint; withdrawn, not overwritten) and part currents (rejected_no_load); it does NOT hold for material submittal status, where sync_register replaces an engineer value with the map's and only the history keeps the old one (G-01). Conflict/staleness is shown through the owner's own fields (candidate/issue rows, `stale` on candidates and verifications, `freshness` on classification, `recheck` on statement rows). Where no mechanism exists it is stated as NONE (samples, classification confirmation endpoint).
