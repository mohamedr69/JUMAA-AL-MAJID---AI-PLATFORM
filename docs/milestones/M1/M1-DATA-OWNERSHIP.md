## How to read the distinctions

- **Processing role** (`SRC.role`) is a routing label; **canonical type** is `CLS.primary_type`; **extracted record category** is `DOC.records[].category`; **business status** is `MS.status` / `SD.revision_status` / `SMP.status` / `CMP.statement.approved`. None of these substitutes for another.
- **File occurrence** = `SRC.document_id`+`SRC.path_relative`; **content revision** = `SRC.sha256`; **logical drawing/document** = `SD.identity`, `MS.identity`, `SMP.identity`; **submission / revision** = `SD.revision`, `MS.revision`, `SMP.revision`; **component/page** = `CLS.component_types` + `DOC.evidence` pages + `DOC.records[].page`.
- **Raw system** lives on records/classification (`DOC.records[].system_code`, `CLS.system_code`); **project-effective system** is `PRJ.system_codes_effective` (system_rules), applied by logs, samples and drawings.
- **Drawing type vs ownership/scope**: type is `CLS.primary_type` (SHOP_DRAWING/IFC_DRAWING/DRAWING); scope (OUR_SCOPE, LIKELY_OUR_SCOPE, RELATED_EXTERNAL, REFERENCE_ONLY, UNKNOWN) has **no field today** - `document_control.is_shop_drawing` uses folder words (enquiry/tender/IFC) and `PRJ.drawings_in_scope` gates the tab. Proposed as a Drawing Processor attribute with conflicting evidence kept (D-04).
- **Consultant comment / contractor response / consultant decision**: comments are evidence (`DOC.records[].reply_text`, `MS.map` cells, `_consultant_words`); the response is `MS.reply_editor`; the decision is `MS.status` / `SD.revision_status` with `source` and history. Target domain and revision are on the register rows.
- **Storage notation**: `Model.column` is a mapped column (line cited); `json:table.column $.path` is a key inside a JSON column and is not a model attribute; `DERIVED` means computed on read and not stored. PROPOSED columns/tables never appear in *current_* columns.
- **Engineer overrides today**: drawing revisions and drawings carry `confirmed_by_id` that reconciliation respects; BOQ lines carry origin=corrected; compliance approval is fingerprinted; part-current rules carry rejected_no_load. Material submittal status has history only: `sync_register` overwrites an engineer status with the map (G-01). Samples and classification confirmation have no override mechanism (G-03, G-02).
- **Classification stage vs freshness**: `CLS.stage_strength` and `CLS.freshness` are separate fields; a supported row can be `source_changed`. No combined state enum is prescribed.
- **Source registries**: ProjectDocument (PDF/Word in the project folder), `PRJ.drf_document_path`/`PRJ.design_sheets` (intake), `IFC.drawing` (DXF uploads/imports), `FWS.schedule_row` (workbook), compliance uploads / ZIP members (`CMP.spec_match`), shared library (`KNW.datasheet_file`), knowledge workbook (`KNW.knowledge_base`), design register workbook (`REG.design_register`).
- **Evidence vs reconciled records vs projections**: evidence = `DOC.records`, `DOC.form_reading`, `DOC.evidence`, `CLS.*`; reconciled = `SD.*`, `MS.*`, `BOQ.*`, `CMP.statement`, `FWS.*`, `IFC.*`; projections = `HOME.*`, `LOG.*`, `SD.register_row`, `SD.summary`, `MS.map`, `MAT.item`, `SMP.board_check`, `HOME.readiness`.
